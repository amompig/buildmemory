# BuildingYourMemory｜企畫基準 v0.1（2026-10-21）

> 狀態：討論定案（信心 95%），可開工。本檔是規則與計畫正本；後續改動在本檔改版號。

## 0. 一句話
到真實城市的地標打卡，拿到那座城市的建築，蓋出自己記憶中的虛擬紀念小鎮。

## 1. 定案表（本次討論結論）

| 項目 | 決定 | 備註 |
|---|---|---|
| 平台 | 手機優先 Web/PWA，桌機同一套 | 不做原生 App |
| 技術 | 純 Three.js + 原生 JS、無 bundler、Cloudflare Pages + Workers/D1、Google 登入 | 台股小鎮路線；帳號沿用 Dies-X |
| 美術 | 程式生成（kit.js 藍圖→模型）+ 少數手工地標 GLB | 手工 GLB 第一版不做 |
| 城鎮 | 一人一座大鎮，各城建築混搭 | 固定 16×16 格，初始開放中央 8×8 |
| 格線 | 正方格；道路 = 塗格子；建築佔 1×1（大型 2×2）；必須鄰路 | 記帳城市式 |
| 第一階段庫存 | **整棟房型**為單位（`machiya ×3`） | 部件層在第二階段 |
| 取得 | **地標打卡為主**；GPS 進入範圍 → 給該地標對應房型 | 拍照第一版不做 |
| 地標來源 | 文化部文資局開放資料（一般級）+ 手挑精選級 | 類型→房型對照表人工校 |
| 重複規則 | 同一地標可重複打卡；重複房型可**拆解**成「記憶碎片」，用來抽細節部件包 | 細節部件在第二階段才可用，碎片第一階段先累積 |
| MVP 範圍 | 只做台灣 | 全球 36 風格留到後面（styles.csv 已備） |
| 社交 | 第一版單機（+ 唯讀分享連結，可選） | 之後：好友、互訪、送部件/房 |
| 未來 | 玩家自組藍圖、上傳部件藍圖（UGC）、拍照辨識 | 第二、三階段 |

## 2. 核心迴圈

```
到訪真實地標 → 打卡（GPS 距離 ≤ R）→ 獲得房型 ×1
   → 城鎮：畫路（2D 俯視）→ 放房（3D 等角）→ 擴張
   → 重複房型 → 拆解 → 記憶碎片 → （第二階段）抽細節部件 → 自組藍圖
```

每日節奏：每天在任一縣市首次開啟 App → 該縣市「通用房型」×1（讓沒去地標的日子也有東西放）。

## 4. 地標資料管線

1. **一般級**：文資局開放資料（國定／直轄市定／縣市定 古蹟 + 歷史建築；含經緯度、類型、所在縣市）→ `scripts/etl_landmarks.py` → `data/landmarks.json`。
2. **對照表** `data/type_map.csv`：文資局「類型／用途」關鍵字 → 房型 id（寺廟→temple、宅第→minnan、日式宿舍→jp_dorm、街屋→shophouse/baroque…），無法對照者 → 該縣市通用房型。
3. **精選級** `data/featured.csv`：手挑，覆寫房型 id、名稱、半徑、說明文字。
4. 兩者合併輸出靜態 JSON，前端載入；更新 = 重跑腳本重新部署（台股小鎮做法）。

授權：政府資料開放授權條款，可商用，需標示來源。

## 5. 系統設計

### 5.1 資料模型（D1）
```
users      (id, google_sub, name, avatar, created_at)
inventory  (user_id, house_id, count)                     -- 整棟為單位
towns      (user_id, grid_json, unlocked_size, updated_at) -- 16×16，每格 {t:'road'|'house', id, rot, lm, at}
checkins   (id, user_id, landmark_id, lat, lng, at)
shards     (user_id, amount)                               -- 記憶碎片
landmarks  靜態 JSON（不進 D1）
```
`grid_json` 整塊 JSON 存取，不做細格 API；衝突以 `updated_at` 後寫者勝。

### 5.2 API（Workers）
```
POST /auth/google
GET  /me                       → inventory + shards + town
POST /checkin {landmark_id, lat, lng}
     伺服器驗證：距離 ≤ R(100 m)、該地標冷卻（每人每地標 24 h）→ inventory[house]++
PUT  /town {grid_json}         → 伺服器驗證：每格房型 ≤ 庫存、房必鄰路、在解鎖範圍內
POST /dismantle {house_id, n}  → inventory−n, shards += n×k
GET  /share/:user_id           → 唯讀城鎮（可選）
```
反作弊第一版：伺服器端距離 + 冷卻 + 速率限制；接受 GPS 偽造風險。

### 5.3 前端分層（比照台股小鎮）
```
index.html      主程式：路由（地圖 / 城鎮 / 規劃 / 倉庫）、狀態、存檔
kit.js          建築部件包：部件函式 + PRESETS 藍圖 → Group（已有雛形）
town.js         城鎮渲染：等角正交相機、格子 → mesh、拖放／旋轉／移除、擴張
planner.js      2D 俯視規劃：Canvas 2D 畫路、檢查鄰路、同步到 grid
geo.js          定位 + 附近地標 + 打卡（含模擬定位除錯面板）
data/           landmarks.json、houses.json
```
效能預算（手機）：≤ 150 draw calls；同房型用 InstancedMesh 或 `mergeStatic`；pixelRatio ≤ 1.5；陰影 1024。

### 5.4 畫面
1. **地圖頁**：Leaflet/MapLibre 真實地圖 + 附近地標 pin + 距離 + 「打卡」按鈕（距離內才亮）。
2. **城鎮頁**：3D 等角；底欄倉庫（房型 × 數量）；拖到格子放置；點房子→旋轉／拆除／看取得地點與日期（記憶卡）。
3. **規劃模式**：2D 俯視，手指塗格子畫路／擦除；不合法格（房未鄰路）標紅。
4. **倉庫頁**：房型清單、拆解成碎片。
5. **除錯面板**（dev 參數開啟）：模擬座標、假打卡、重設存檔。

## 6. 開發順序（快速迭代）

| Sprint | 產出 | 驗收 |
|---|---|---|

## 7. 可調參數（先給預設值）

| 參數 | 預設 |
|---|---|
| 打卡半徑 R | 100 m（精選地標可個別設） |
| 同地標冷卻 | 24 h |
| 每日縣市簽到 | 通用房型 ×1 |
| 拆解比率 k | 1 棟 → 1 碎片；1 部件包 = 5 碎片 |
| 城鎮 | 16×16；初始 8×8；每放滿 70% 解鎖一圈 |
| 建築大小 | 1×1；夥房／廟 2×2 |

## 8. 風險
- **GPS 偽造**：第一版接受；第二階段可加拍照證明。
- **iOS Safari 定位**：只能前景取得，需使用者主動按打卡；不做背景計步。
- **風格差距**：程式生成到不了紀念碑谷精雕質感；靠調色、移軸、倒角拉近。
- **文資局資料品質**：類型欄位不一致，對照表需人工校；精選級補洞。
- **手機 WebGL**：16×16 全放滿時需 instancing；Sprint 0 先量測。
