支持度：3/3 = 三次都提出；2/3 = 兩次；1/3 = 僅一次（列為可選）。

## 2. 架構提案（共識）
- `rules.js`（純函式，雙端共用）、`store.js`（單一狀態 + localStorage 立即寫 + 2 s debounce 同步 + version）、`api.js`（fetch 封裝、401/409 回呼）、`kit.js`（藍圖 → 烘焙幾何 + footprint）、`town.js`（InstancedMesh 池、raycast）、`planner.js`、`geo.js`、`functions/api/*`（auth/me/checkin/daily/town/dismantle/share）、`scripts/etl_landmarks.py`。
- Grid 格式（1/3 提出，無反對）：256 長陣列，`null | {t:'road'} | {t:'house',id,rot,ref} | {t:'part',of:idx}`（2×2 從屬格）。
- 可選（1/3）：打卡附 `accuracy`，伺服器接受距離 ≤ R + min(accuracy, 50)；Sprint 1 用 cookie `device_id` 匿名打卡，登入時合併；Playwright `setGeolocation` E2E。

```
GPS → geo.js ─POST /checkin─▶ rules 驗證 ─▶ batch(checkins/grant, inventory) ─▶ GET /me → store
store(grid,version) → planner/town 編輯 → rules.validate → localStorage
   → PUT /town{grid,base_version} → 200{version} / 409{server grid} → 使用者二選一
```
