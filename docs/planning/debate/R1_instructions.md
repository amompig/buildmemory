# 交叉詰問 第 1 輪 指令

你將讀到五個角色（工程師、資安、UI 設計師、架構師、使用者）各自合併後的方案 `merged/01–05`。你以**自己的角色**對**其他四個角色**的方案提出詰問：找出與你專業衝突、對一人開發不切實際、互相矛盾、或會傷害你所代表的利害關係人的提案。

規則：
- 定案（spec_v0.1 的定案表 + context.md 的技術定案）不可推翻。
- 每條詰問要指名對象角色與其具體提案，說明為何有問題，並給你的替代方案；若兩個角色的提案互相矛盾，指出來並選邊。
- 也列出你**無條件接受**的他人提案（讓最終整合知道哪些已無爭議）。
- 不要重複自己方案；不要客套。

輸出格式（繁體中文，≤ 700 字）：
```
# <角色> 詰問 R1

## 詰問（最多 6 條，依重要性排序）
| # | 對象 | 被詰問的提案 | 問題 | 我的替代方案 |

## 矛盾點（他人方案彼此衝突，我選邊）
- <A 角色說 X，B 角色說 Y> → 我選 __，因為 __

## 無條件接受
- <角色：提案>（條列）

## 我願意讓步的自家提案（最多 3 條）
```
