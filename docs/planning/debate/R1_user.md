## 矛盾點（他人方案彼此衝突，我選邊）
- 工程師「首登只匯 grid」vs 架構師「/claim 上傳帳本排除 debug」→ 選架構師，免登入先玩是我方第一需求。
- 架構師「離線打卡排隊補送」vs 資安「速度檢查用伺服器時間拒絕」→ 選排隊，山區離島沒訊號是真的；補送用記錄當時的時間，只記錄不拒。
- 架構師「counties.json」vs 工程師「最近地標判縣市」→ 選工程師，體驗一樣、便宜很多。
- 資安「定位同意畫面」vs 我方「打卡鈕旁一句話」→ 選一句話＋系統原生提示，不加整頁關卡。

## 無條件接受
- 資安：不存原始座標；分享隨機 token、預設關、剝除地點日期；刪帳與匯出；授權標示。
- 工程師：Sprint 0 延長、先 3 房型＋色塊占位；API 同源。
- 設計師：2D 併入 3D 同場景；全幅記憶卡；首啟預鋪路＋引導；相機 fit、4 向快照；紅框＋斜線＋震動。
- 架構師：正式訪客模式；每棟一列實例帳本（「變體」「第 N 次到訪」需要每棟自己的種子與來源）；rules.js 共用。

## 我願意讓步的自家提案（最多 3 條）
1. 自動帶入天氣／時段：砍掉，心情 5 鍵可跳過＋一句話就夠。
2. 擴張改打卡數解鎖：保留 70%，接受設計師的進度條與解鎖儀式。
3. 每日簽到給裝飾件：第一版可給鐵窗厝，但要色票變體且上限 3 棟；首啟送房讓步到 2 棟。
