## B. 投票
1. 兩態：模式越少越像記帳城市；擺放中「道路」只是底欄第一格。
2. 日上限 30；accuracy 200 m：到頂與訊號弱都有專屬一句話，不會像壞掉。
3. 錯誤碼＋數值：按鈕預檢與伺服器拒絕共用同一句，dist 取整到 10 m。
4. Code 先打通 3 房型；但錯誤碼 enum 與 grid schema 由 Cowork 先定，ui_strings 才有鍵可寫。
5. 第一版不做：離線只 toast「有訊號再按」，鎮仍可看可編輯快取版。
6. 通用房 ×1 色票變體、上限 3；到頂時 grant 直接以 `dismantled` 入帳＝1 碎片，文案「鐵窗厝滿了，收為碎片」，每天仍有東西拿。
7. 接受＋一處修改：縮圖用 Canvas 2D 畫 grid，不開第二 WebGL；對話只在「看」模式彈出。
8. 接受＋一處修改：心情與一句話放在記憶卡同一畫面，不另成步驟；5 鍵用自家 SVG 圖示，跨平台一致。
9. 保留 70%＋進度條與解鎖儀式：純 grid 函式，進度可即時顯示。
10. 2 棟＋預鋪路：兩棟不同房型，第二次放置才練到鄰路規則。

## C. 底線與提醒
1. **單一場景、三 tab**：規劃是相機俯視＋筆刷，沒有獨立 2D 頁與第二套座標。
2. **每個失敗都有一句人話＋數值**（too_far／weak_signal／cooldown／rate_limited／409／401）；UI 不得出現裸錯誤碼或無說明的灰按鈕。
3. **可用性硬指標**：觸控 ≥44 px、對比 ≥4.5:1、紅框＋斜線＋震動雙編碼、`prefers-reduced-motion` 關後製；DOM 疊層只讀 state 發 intent。

提醒整合者：按下打卡到看到記憶卡之間不得超過 2 個畫面；每個新步驟先問「它能不能直接放在記憶卡上」。
