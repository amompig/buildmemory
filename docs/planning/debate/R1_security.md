# 資安 詰問 R1

## 詰問（最多 6 條，依重要性排序）
| # | 對象 | 被詰問的提案 | 問題 | 我的替代方案 |
|---|---|---|---|---|
| 1 | 架構師、使用者、工程師 | 免登入訪客模式；登入時匯入本機帳本（全匯／非 debug／cookie `device_id` 合併） | localStorage 可改，匯入＝客端自證庫存；無簽章 `device_id` 自填即換身分、冷卻失效；訪客打卡記在伺服器＝無主行蹤，無人能刪 | 訪客只有本機 grid＋首啟贈品；訪客打卡仍走 `/checkin`，`device_id` 伺服器發、HMAC 簽、HttpOnly，同限速冷卻；登入 `POST /claim` 只綁 device→user，不收客端帳本；未綁定資料 30 天清 |
| 2 | 架構師 | 離線 pending ops，客端時間 24 h 有效 | 客端時間＝冷卻、速度、日上限全失效，可離線編一批再重放；座標落地 localStorage 等上線，違反「座標即丟」 | 第一版不做（選 1/3 反對方）。若做：佇列 ≤3、`at` 用伺服器收到時間、重放仍驗距離冷卻（只保證不丟）、送出即清、UI 標示「待送 N 筆含位置」 |

## 矛盾點（他人方案彼此衝突，我選邊）
- 架構師 2/3 離線排隊 vs 架構師 1/3、使用者 1/3 須線上 → 選線上，冷卻與速度只有伺服器時間可信。
- 工程師「首登只傳 grid 草稿、庫存以伺服器為準」vs 架構師「全匯／`/claim` 傳帳本」vs 使用者「本機存檔不丟」→ 選工程師，加 #1 的 device 綁定即同時滿足「不丟」。
- 工程師 Pages Functions 同源 vs 架構師獨立 Worker → 選同源，SameSite cookie 才可用。
- 使用者「自動天氣」vs 我方「座標不出境」→ 選時段；天氣可選且只用地標座標。

## 無條件接受
- 工程師：`rules.js` 雙端共用；`version`+409；D1 batch 原子驗證；實例制 grants；dev 資料不上傳；打卡附 `accuracy`。
- 架構師：通用帳本 + state；格子命名空間 `sys:/u:`；JSON Schema v1；localStorage 登入後不當權威。
- 設計師：DOM 疊層只讀 state 發 intent（利於 CSP、免 innerHTML）；geo.js 只在按下時定位。
- 使用者：打卡鈕旁隱私一句話；不存原始座標；分享預設不含地點日期；匯出與刪帳；精選半徑 150–200 m。

## 我願意讓步的自家提案（最多 3 條）
1. 保存期限彙整為計數 → 撤回：`checkins(lm, at, mood, note)` 為記憶卡正本永存（使用者可刪），只有 `dist_m/accuracy` 90 天清。
2. 速度門檻 150 km/h → 350 km/h（高鐵台北→台中 1 h 會誤殺），另加「同小時跨縣市 ≤2」。
3. 日上限 20 → 30 次；拒收 `accuracy>150 m` → 200 m，距離容差仍 ≤ R+min(acc,50)。
