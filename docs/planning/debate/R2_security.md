## B. 投票
1. 兩態：狀態少一個，誤操作與文案都少。
2. 日上限 30；accuracy 200 m：30 已涵蓋古蹟密集區一日行程，到頂顯示「明天再來」。
3. 錯誤碼＋數值：前端預檢與伺服器拒絕共用 `rules.js` 同一函式。
4. Code 先打通 3 房型；但 API 請求 schema（grid 256 格、enum、body 上限）與錯誤碼 enum 由 Cowork 先定，因為那是 guard。
5. 第一版不做：只留 `op_id` 冪等欄。
6. 通用房 ×1 色票變體、上限 3：不加格子型別；`kind=decor` 先開 enum。
7. 接受：草稿只存 localStorage，不進 D1。
8. 接受：mood enum、note 伺服器 NFC 正規化 ≤40 字、前端 `textContent`、不進 `/share`。
9. 保留 70%：純 grid 函式，無可操弄的伺服器計數。
10. 2 棟＋預鋪路：贈品由伺服器發給 `device_id`，grid 首日即合法。

## C. 底線與提醒
1. **客端自報的身分、時間、庫存一律不信**：`device_id`／session 伺服器簽發，`at` 一律伺服器時間，grant 只由伺服器發，沒有任何匯入 API。
2. **原始座標不落地**：不進 D1、log、localStorage，不送第三方；`/share` 為 opt-in 隨機 token、可撤銷，投影只含 `t,id,rot`。
3. **刪帳與匯出第一版就有**；每個自由文字入口（note）必有伺服器長度／正規化＋前端 `textContent`＋CSP。

提醒整合者：每多一個客端時間或使用者輸入欄位，就多一個後門；先問「它能不能由伺服器產生」。
