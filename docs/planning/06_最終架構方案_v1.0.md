## 0. 相對 v0.1 的變更（使用者已裁決）

| 項目 | v0.1 | v1.0 |

| 庫存 | `inventory(house_id,count)` + `shards` | **單一帳本 `grants`**，每棟一列（kind/state/seed/mood/note/visit_n）；碎片 = dismantled 列數 |
| 記憶卡 | 地標、日期 | + **心情 5 鍵（可跳過）+ 一句話 ≤40 字（可空）+ 第 N 次到訪**，與打卡同一畫面 |
| 重複打卡 | 同一棟 | 第 2 棟起**色票變體**（seed），不改幾何 |
| 每日簽到 | 通用房 ×1 | 通用房 ×1 色票變體，**持有上限 3**，到頂改給 1 碎片 |
| 冷卻 | 滾動 24 h | **台灣自然日 04:00 重置**，`UNIQUE(user, lm, day)` |
| 反作弊 | 距離 + 冷卻 | + 日上限 40、最小間隔 60 s、`accuracy > 200 m` 拒收、距離容差 `R + min(acc, 50)`；**無速度檢查** |
| 城鎮存檔 | `updated_at` 後寫者勝 | 伺服器 `rev` 整數 + 409；開 App 先拉伺服器版 |
| 位置資料 | 存 lat/lng | **不存原始座標**，只存 `landmark_id, at(伺服器時間)`；座標驗完即丟 |
| 分享 | `/share/:user_id` | opt-in 隨機 token、預設關、只含 `t,id,rot`；**分享圖純客端產**（Sprint 3） |
| 規劃模式 | 獨立 2D 頁 | **併入 3D 同場景**：相機補間到俯視 + 塗格筆刷 |
| 手勢 | 未定 | 三 tab（地圖/城鎮/倉庫）× **兩態**（看/擺放）；4 向相機快照；幽靈放置 + 確認 |
| 首啟 | 空地 | 送 **2 棟不同房型 + 預鋪一條路** + 三步引導；不登入、不先要定位 |
| API 位置 | 獨立 Worker | **Pages Functions 同源 `/api/*`**（cookie 才可用） |
| Sprint 0 | 1–2 天、8 房型 | **3–4 天、先 3 房型**（iron/minnan/shophouse）打通核心迴圈 |
| 每日簽到 | 首次開啟自動給 | 當日首次定位成功時由前端呼叫 `POST /api/daily`（需定位才能判縣市）；離線或拒絕定位當日不發 |
| 帳號 | 沿用 Dies-X | 同一 Google OAuth client 加新 origin，但 **D1 與 session 獨立**（一處外洩不波及兩專案） |
| 解鎖範圍 | `towns.unlocked_size` 欄位 | 由 `rules.unlock(grid)` 純函式推導，不存欄位 |
| 砍掉 | — | 離線排隊打卡、自動天氣、示範鎮動畫、獨立定位同意頁、後端 cron、速度檢查、counties.json、分縣懶載、音效、`users.name/avatar`（第一版無需暱稱） |

## 2. 系統架構

### 2.1 前端模組（上限 10，依賴單向 views → store → rules）
| 模組 | 職責 | 不做 |
|---|---|---|
| `index.html` | 啟動、路由三 tab、載入 data | 業務邏輯 |
| `shared/rules.js` | 純函式：鄰路、2×2 佔格、解鎖 70%、距離/容差、冷卻日、日上限、錯誤碼 | three/DOM/網路 |
| `store.js` | 單一狀態（grants, grid, rev, ui）+ localStorage 快取 + 2 s debounce 同步 | 渲染 |
| `api.js` | fetch 封裝、401/409 回呼、op_id | 狀態 |
| `kit.js` | houses.json 藍圖 + seed → `bake()` 合併幾何 + footprint | 場景/狀態 |
| `town.js` | grid → 每房型 InstancedMesh（instanceColor 變體）、道路池、幽靈格、高亮、相機 fit/4 向、俯視補間 | 改狀態 |
| `edit.js` | 語意事件 → rules 驗證 → store 修改（塗路/落房/拆除/旋轉） | DOM/three |
| `gestures.js` | tap/長按/pan/pinch → 依兩態分派語意事件 | 規則 |
| `geo.js` | 按打卡時 `getCurrentPosition` 一次、附近地標、Leaflet 地圖頁、模擬定位面板 | 存座標 |
| `ui.js` | DOM 疊層：tab、工具列、倉庫抽屜、記憶卡、引導、toast、409 對話、分享面板 | 碰 three |

### 2.2 後端（Pages Functions 同源，3 檔）
- `functions/api/[[path]].js`：路由 + `guard()` 包裝（Origin、session/device、body ≤ 32 KB、schema、限速計數）
- `functions/_lib/handlers.js`：各端點邏輯，驗證只呼叫 `shared/rules.js`
- `shared/rules.js`：與前端同一檔
- 零程式碼項：Cloudflare Rate Limiting（/checkin 30/min/IP、/auth 10/min/IP）、Pages `_headers`（CSP/HSTS）、D1 Time Travel、`wrangler secret`
- `landmarks.json` build 時整檔內嵌（< 1 MB），帶 `data_version`；前端版本不符即重載

### 2.3 D1 資料模型
```
users    (id UUID PK, google_sub NULL UNIQUE, device_hash UNIQUE, share_token NULL, created_at, last_seen)
grants   (id PK, user_id, kind ∈{house,part,shard,decor}, item_id 'sys:minnan', state ∈{stock,placed,dismantled},
          seed INT, landmark_id NULL, visit_n INT, mood NULL ∈{0..4}, note NULL ≤40, at(伺服器時間), op_id UNIQUE, consumed_at NULL)
checkins (user_id, landmark_id, day 'YYYY-MM-DD'(台北−4h), grant_id, dist_m)  UNIQUE(user_id, landmark_id, day)
towns    (id PK, user_id, grid_json ≤32 KB, rev INT, updated_at)              -- id 獨立，預留第二座鎮
```
- 碎片 = `COUNT(grants WHERE state='dismantled' AND consumed_at IS NULL)`
- 可用庫存 = `stock` 列；放置時 state→placed、拆除→stock；拆解→dismantled
- 第二階段：`kind=part`、`blueprints` 表、格子 `u:<uuid>`；第三階段：grants 轉讓列、`relations`。**每項擴充 = 加 kind 或加一列，不改表。**

### 2.4 Grid 格式
256 長陣列：`null | {t:'road'} | {t:'house', id:'sys:minnan', ref:grantId, rot:0–3} | {t:'part', of:idx}`（2×2 從屬格）。

### 2.5 API
| 端點 | 動作 | 伺服器驗證 |
|---|---|---|
| `POST /api/session` | 簽發 device cookie、首啟贈品（2 棟 + 預鋪路 grid） | 一次性 |
| `POST /api/auth/google` | 驗 id_token（JWKS、iss/aud/exp）→ 綁 `google_sub`，發 30 天滑動 session | Google 帳尚無資料 → 直接綁定；已有資料 → **合併規則**：grants 全部併入（state 一律改 stock）、town 以 Google 帳為主、device 帳的 grid 退回本機草稿 30 天；device 帳標記 merged |
| `GET /api/me` | grants + town + shards + data_version | — |
| `POST /api/checkin {lm, lat, lng, acc, op_id}` | 發 house grant（seed、visit_n）+ checkins | `acc ≤ 200`、`dist ≤ R + min(acc,50)`、`UNIQUE(lm,day)`、日 ≤ 40、間隔 ≥ 60 s；座標即丟 |
| `POST /api/daily {lat, lng, op_id}` | 發通用房或碎片 | 每日 1 次；縣市 = 最近地標 ≤ 30 km；iron 持有 ≥ 3 → 碎片 |
| `PUT /api/town {grid, base_rev}` | 存鎮，批次更新 grant state | schema、鄰路、解鎖範圍、ref 歸屬、`placed ≤ stock+placed`；rev 不符 → 409 + 伺服器版 |
| `PUT /api/grant/:id/memory {mood, note}` | 記憶卡 | mood enum、note NFC 正規化 ≤40 |
| `POST /api/dismantle {ids}` | state→dismantled | 僅 stock 列 |
| `GET /api/me/export`、`DELETE /api/me` | 個資權利 | — |
| `POST/DELETE /api/share`、`GET /api/share/:token`（Sprint 3 可選） | opt-in 唯讀 | 投影只含 `t,id,rot` |

錯誤碼（`rules.js` 與 `ui_strings.json` 共用鍵）：`too_far{dist}`、`weak_signal`、`cooldown{until}`、`rate_limited{retry_after}`、`daily_cap`、`conflict{rev}`、`unauthorized`、`invalid`、`offline`（前端專用：「有訊號再按」）。`unauthorized`（401）只重新取 session，**不清本機 grid**。

## 3. 玩家流程（定案）
1. 首啟：不登入不定位 → 空地 + 預鋪路 + 2 棟（不同房型）→ 三步引導（塗路→放房→去地圖）。
2. 地圖 tab：進入時取定位一次；當日首次定位成功 → 自動呼叫 `/daily` → toast「今天的通用房已入倉庫」（或「鐵窗厝滿了，收為碎片」）。列表顯示最近 3 個地標、距離/步行分鐘、預告房型；進入 R 範圍按鈕亮；100–150 m 顯示「再走約 30 m」；無網路時打卡鈕顯示「有訊號再按」，小鎮與附近清單仍可看快取版。
3. 打卡：按下 → 取定位一次 → 成功 → 記憶卡（地名、日期、第 N 次、心情 5 鍵、一句話，「略過」與「存」同大）→「放進小鎮」直入擺放。
4. 城鎮 tab：兩態。看：單指平移、雙指縮放、4 向按鈕。擺放：底欄選道路或房 → 單指塗路/幽靈落房 → 綠/紅 + 斜線 + 震動 → 完成。
5. 倉庫 tab：依日期 + 縣市 chips 排序（= 時間軸）、拆解、碎片數。
6. 衝突：開 App 先拉伺服器版；真衝突只在「看」模式彈兩張 Canvas 2D 縮圖 + 裝置/時間，預設較新，輸的存本機草稿 30 天。
7. 登入：第一次打卡成功後、換裝置、或想分享時提示；絕不擋在前面。
8. 分享（Sprint 3）：主 canvas `toBlob` + Web Share；預設只含小鎮 + 棟數；縣市/日期/地標名三個勾選預設關、放在分享面板上一步可點。

## 6. 五方底線（整合者承諾）
- 工程：庫存只信伺服器 grants；規則只在 rules.js；渲染預算不過不排新功能。
- 資安：客端自報的身分/時間/庫存一律不信；座標不落地；刪帳與匯出第一版就有；每個自由文字有正規化 + `textContent` + CSP。
- 設計：單一場景三 tab；每個失敗一句人話 + 數值；觸控 ≥ 44 px、對比 ≥ 4.5:1、雙編碼、reduced-motion。
- 架構：依賴單向；單一帳本；內容歸 JSON、狀態歸 D1、localStorage 只快取；前端 ≤ 10 模組、後端 3 檔、無 cron。
- 使用者：免登入先玩且不丟；失敗說人話、高鐵不被當作弊；記憶卡綁單棟、拆解後仍可翻。
