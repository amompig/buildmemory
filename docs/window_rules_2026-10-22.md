# 窗戶排查 — 方向、樣式、節奏、深度（2026-10-22）

> 依《立體感與線條一致性 MEMO》的六步與《專有詞彙指南》逐項排查窗戶。結論：窗戶違和不是色彩問題，是**投影、節奏、立面分節、形式語言**四項同時不合規則。四項都已在渲染器與 blueprint v2.2 修正，兩塊畫布與 `data/*.json` 已更新。

## 1. 排查結果

| 檢查項（指南用語） | 之前 | 違反的規則 | 修正 |
|---|---|---|---|
| **投影 Axonometric Projection** | 每扇窗是一個**螢幕對齊的直立矩形**（5×7 px），不隨牆面傾斜 | 軸測投影中，同方向平行線必須保持平行；牆面上的矩形在畫面上是 2:1 的平行四邊形。直立矩形 = 貼在畫面上的貼紙，東面窗尤其「方向錯了」 | 窗戶改為**畫在牆面平面內**的多邊形：以 (t, z) 參數化南面 / 東面，四角沿牆面邊線；拱窗、圓窗的弧也在該平面內取樣 |
| **節奏與重複 Rhythm** | 窗列數 = `min(樓層, 3)`，橫帶數 = `bands`；兩者不同時，窗落在橫帶線上或兩帶之間不等分（總統府 3 列窗 vs 5 條帶） | 窗距、柱距與樓層分割要形成同一規律 | 一層一排：`rows = winRows ‖ bands ‖ floors`，窗心在每層 0.55 高；橫向每面以 `faceLen / 0.26` 上限控制密度（最小窗距 0.26 格） |
| **比例與尺度 Proportion** | 所有窗同一 5×7 px，與量體無關；小廟的窗和 101 裙樓的窗一樣大 | 門窗要與樓層、人體尺度一致 | 以格為單位：rect 0.14×0.16、arch 0.14×0.20、round ⌀0.16、lattice 0.12²、strip 0.5×0.09（隨 zoom / vScale 縮放） |
| **立面分節 Facade Articulation** | 框 1 px + 亮色玻璃，無深度 | 窗要內凹，不能只是表面色塊 | 框（牆色 0.6）+ **側壁 jamb**（0.03 格；南面窗的側壁朝東、用東面色；東面窗的側壁朝南、用南面色——與光照法線一致）+ 玻璃 |
| **形式語言 Formal Language** | 全部同一種方窗；拱窗只是圓角；廟宇、古厝也是亮黃直窗 | 細節規則要和類型一致 | `wstyle`：rect（官署、公寓）/ arch（博物館、賓館、監察院、紅樓、街屋三連拱）/ round（北門）/ lattice 木格小方窗（龍山寺、林安泰、三合院、小廟）/ shoji 紙門（日式宿舍）/ strip 帶狀玻璃（101 裙樓、鐵皮工廠高窗）/ none（紀念堂、101 塔身、圓山主體） |
| **明暗 Light and Shadow** | 玻璃一律暖黃 #F3E7C8，像夜景點燈，與日景地面衝突 | 光影要表達表面朝向，不能製造矛盾光源 | 日景玻璃改為冷灰藍 #5F6E7B（東面再 ×0.88）；只有 shoji 紙門用暖白；lattice 用深木色 |
| **線條層級 Line Hierarchy** | 窗框線與量體轉折線等粗 | 主輪廓 > 轉折 > 細節 | 角線 1.2 px 最深 → 簷口板 2.5 px → 窗框 1 px 牆色 0.6 → 側壁 0.03 格。窗框不再是獨立深色描邊 |
| **門** | 螢幕對齊的圓角矩形 | 同投影問題 | 門也畫在南面平面內（rect / arch），有側壁；有 `arch` 挖洞的量體不再疊畫門 |
| **門面一樓** | 門與窗重疊 | 入口要有主從關係 | 有門 / 拱洞的南面一樓：中央一格不開窗；窗數 ≤ 2 時整排不開 |

## 3. 給 kit.js 的對應

1. 窗是**部件層**（kind=part）：每個 block 的 `window`（樣式）+ `windowCols` + `winRows` + `winFaces` 決定實例化的窗部件；部件幾何是「框 + 內凹 0.03 格的玻璃面」，不是貼圖。
2. 一層一排、窗心 0.55 層高，與 `bands` 共用同一個 floorH；這是 bake 時的硬規則，避免窗落在橫帶上。
3. 玻璃材質日景用冷灰藍、夜景只改發光（不改幾何）；shoji 例外為暖白。
4. 東面窗與南面窗是同一部件旋轉 90°，側壁方向自然正確；不要為兩面各做一個貼圖。
